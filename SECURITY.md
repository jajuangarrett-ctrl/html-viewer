# Rendering boundary

The host only reads supported files in a selected logical vault project. Root-level single files expose only themselves. Dot-prefixed paths and non-supported extensions are excluded. Limits are checked before and after reads. The host performs no filesystem writes for page actions, no network fetch on behalf of a page, and exposes no general vault-open/file-read/native bridge. Obsidian manages the actual underlying filesystem: logical scoping is not a claim that this plugin independently detects symlinks on every adapter.

Raw HTML is parsed with pure JavaScript `parse5`, then reconstructed in a template's inert owner document. This prevents the pre-sanitization image/frame-fetch hazard of `DOMParser`. Resources are rewritten to project-local data URLs before any page is mounted. CSS is parsed and local URLs/imports rewritten. A CSP precedes the bootstrap and document content. Safe mode additionally sanitizes with DOMPurify and removes active elements, forms, script/event code, frames, refresh metadata and original anchor URLs.

The live iframe has only `sandbox="allow-scripts"`. It never receives `allow-same-origin`, popups, forms, top navigation or downloads. Nonce-only script policy permits the host's bounded reader bootstrap in safe mode, not original scripts. Message handling checks both the current iframe source and per-load nonce, then only allows title/section metadata and controlled link proposals. Links are resolved against the project's relative path, not the whole vault. No content is fetched from a URL supplied in a message. Reloading/replacing a page changes the nonce. Forged legacy `open-vault-file` messages have no handler.

Trusted mode intentionally runs a reviewed document's code in this opaque frame and bundles supported project resources for a local fetch shim. Because browser sandbox/CSP cannot stop all self-navigation, it is not a no-network promise. It can leak scoped project data. This is disclosed immediately before enabling and in Page Options. Safe mode remains the default; truthy strings cannot silently enable trust or external links on load.

External navigation requires the off-by-default setting plus a destination confirmation; the URL itself may contain data and must be reviewed. An explicit supported-video Load creates a separate provider iframe, not a network permission for the local HTML. The mock-video tests prove load timing/lifecycle, not provider availability or absence of YouTube tracking.

Browser tests intercept network from before document preparation, verify no hostile probe requests in safe mode, and exercise opaque-parent isolation and project fetch boundaries. This is a bounded application test, not a formal audit or a guarantee about all future web-engine vulnerabilities.
